# Findings

## Requirements

- User wants implementation of camera + joint-state standard ACT data collection.
- Existing project already has teaching mode and zero-torque dragging.

## Code Findings

- `el_a3_sdk/MotorStudio/backend/trajectory_recorder.py` records only timestamped joint positions into JSON.
- `el_a3_sdk/MotorStudio/widgets/teaching_panel.py` samples current joint positions from GUI feedback at a configurable rate.
- `el_a3_sdk/el_a3_sdk/interface.py` exposes `GetArmJointMsgs()`, `GetArmJointVelocities()`, and `ZeroTorqueModeWithGravity()`.
- `ela3_motion/hardware.py` has reusable SDK path/CAN setup helpers and interface kwargs.

## Technical Decisions

- New data collection should not mutate existing teaching JSON behavior.
- A CLI-first collector is lower risk than modifying the PyQt GUI immediately.
- HDF5 datasets should be extendable because episode duration is unknown at start time.
- Training should consume the same HDF5 schema generated by `ACTEpisodeWriter`.
- First local policy should be ACT-style and practical rather than a full CVAE ACT reproduction: image/qpos conditioning plus learned action queries for chunked action prediction.
